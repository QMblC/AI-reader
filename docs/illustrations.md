# Иллюстрации и временное хранение

Реализация следует [согласованной концепции](https://chatgpt.com/share/6af479b6-93f4-83ed-98af-4b0589f45472): один Spring Boot процесс, Application управляет проверкой кэша, вызовом AI и сохранением. PostgreSQL хранит переводы, объяснения и технические метаданные заданий; изображения лежат на диске. `ImageStorage` позволяет добавить S3-адаптер без изменения сценария и HTTP API. Для перехода потребуется перенести файлы и заменить конфигурацию адаптера.

## Запуск

1. Требуется Java 21 или новее и PostgreSQL 17. С Docker: `docker compose up -d postgres`. Либо создайте отдельную БД `aireader` и пользователя в существующем локальном PostgreSQL.
2. Скопируйте `.env.example` в `.env`, заполните `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. Используется существующий ключ Yandex; ему нужен доступ к текстовым моделям и генерации изображений. `.env` исключён из Git и автоматически загружается Spring. Окружение процесса имеет приоритет.
3. Укажите `DATABASE_URL`, `DATABASE_USERNAME`, `DATABASE_PASSWORD`. Flyway создаёт таблицы кэша в выбранной БД. Для непустой БД без Flyway используйте отдельную схему/БД: автоматический baseline не включён.
4. `./mvnw.cmd spring-boot:run` (Windows) или `./mvnw spring-boot:run` (Linux). Swagger: `/swagger-ui/index.html`.

При `ILLUSTRATION_ENABLED=false` POST иллюстраций возвращает `503 ILLUSTRATION_DISABLED`. При `YANDEX_ENABLED=false` анализ использует прежнюю заглушку. PostgreSQL требуется в обоих случаях. Для локального диска нужен каталог с правом записи, по умолчанию `./data/images`; он исключён из Git.

## API и сессия

Сервер возвращает случайный UUID v4 в `X-Reader-Session` и HttpOnly-cookie `AI_READER_SESSION`. Браузер сохраняет cookie; мобильный клиент должен сохранить заголовок и повторять его во всех запросах анализа, генерации, статуса и файла. Можно заранее сгенерировать UUID v4 на клиенте. Отсутствие сессии создаёт новую область кэша. Некорректный токен — `400`, чужой или просроченный ID — `404`. Заголовок имеет приоритет над cookie.

Это анонимная сессия с секретным токеном, а не авторизация пользователя: токен даёт доступ к её результатам. При добавлении аккаунтов область кэша нужно привязать к проверенному principal. Во внешней среде используйте HTTPS. Ответы API и изображения имеют `Cache-Control: no-store`.

`POST /api/v1/illustrations`:

```json
{
  "book": "",
  "author": "",
  "edition": "",
  "selectedText": "The old castle stood on a hill, surrounded by a dark forest.",
  "context": "It was evening. A lone traveller approached the castle.",
  "style": "BOOK",
  "size": "SQUARE"
}
```

`style`: `BOOK` (по умолчанию), `WATERCOLOR`, `REALISTIC`, `COMIC`. `size`: `SQUARE` (по умолчанию, 1024×1024), `PORTRAIT` (1024×1536), `LANDSCAPE` (1536×1024). Книга, автор и издание необязательны. Контекст должен содержать только прочитанную часть: сервер не знает позицию чтения и не может проверить это условие за клиента.

Ответ `202 Accepted` содержит `id`, `status`, `createdAt`, `expiresAt`; `Location` и `Retry-After: 2` указывают, куда и когда обращаться за статусом. Опрос: `GET /api/v1/illustrations/{id}`. При `READY` возвращается `200` с `imageUrl`; этот относительный URL отдаёт PNG/JPEG. При `FAILED` возвращается `200` со статусом и безопасным `errorCode`: клиент должен проверять статус. Одинаковый POST возвращает существующее задание, включая ошибку в течение её короткого TTL.

Ошибки запроса: `400` — валидация, `429` — лимит/переполненная очередь, `503` — функция выключена. Фоновые ошибки отражаются в `errorCode`: например `IMAGE_PROVIDER_ACCESS_DENIED`, `IMAGE_PROVIDER_RATE_LIMIT`, `SCENE_PROMPT_TOO_LONG`, `INVALID_IMAGE_RESPONSE`, `GENERATION_INTERRUPTED`. Тела ошибок провайдера, ключи, исходный текст и промпты не возвращаются и не логируются.

## Экономия и контракт Yandex

На 11 ноября 2026 года выбрана `aliceai-image-art-3.0` через `/v1/images/generations`. По [официальным тарифам](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing) одна новая генерация стоит 2,23 ₽ с НДС. Подготовка описания через `yandexgpt-lite` оплачивается отдельно: 0,20 ₽ за 1000 входящих и исходящих токенов в синхронном режиме. Это недорогой вариант с уже используемым ключом; минимальная цена среди всех провайдеров не гарантируется.

Сначала Lite составляет описание до 450 символов; ответы свыше лимита 500 символов отклоняются до вызова генератора. Затем отправляются только `model`, `prompt`, `size`; неподдерживаемые `quality`, `n`, `response_format` не передаются. [Контракт](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/images-generation), [модели и лимиты](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models). Поддерживается один результат в Base64; проверяются формат PNG/JPEG, размер до 10 МБ и габариты до 4096×4096. Вызовы выполняются с `x-data-logging-enabled: false`.

Приложение не повторяет платные POST автоматически: при сетевом сбое провайдер уже мог принять запрос. Одна рабочая нить, очередь из четырёх заданий, общий лимит POST анализа и иллюстраций — `RATE_LIMIT_REQUESTS_PER_MINUTE`. `ILLUSTRATION_TIMEOUT` — таймаут отдельного обращения, по умолчанию 120 секунд (для двух этапов время суммируется); соединение — 5 секунд. Модели — `ILLUSTRATION_MODEL` и `ILLUSTRATION_SCENE_MODEL`.

## Кэш и очистка

- SHA-256 учитывает сессию, все поля `TextContext`, модель/провайдера, параметры и содержимое системного промпта; для изображений также стиль и размер. Нормализуются Unicode NFC, края строк и CRLF. Значимые пробелы внутри текста сохраняются.
- Проверка кэша предшествует обоим AI-вызовам. TTL фиксирован от создания, максимум 48 часов; попадание в кэш его не продлевает. Ошибки генерации сохраняются на 5 минут. Промпты и входной текст отдельно не сохраняются.
- Одинаковые параллельные иллюстрации объединяются уникальным ключом PostgreSQL; текстовые запросы — блокировками внутри процесса. Кэши анализа и изображения независимы.
- Просроченное содержимое сразу недоступно. Планировщик каждые 60 секунд удаляет просроченные записи и файлы; физическое удаление может отставать на интервал очистки и время простоя сервера. Удаляются также файлы без метаданных. Кэш не является постоянной галереей; клиент может скачать изображение себе.
- При перезапуске незавершённые задания получают `FAILED/GENERATION_INTERRUPTED`, автоматический повтор не выполняется. Исходные запросы на диске не сохраняются. Поддерживается **один экземпляр приложения**; несколько реплик потребуют общей очереди/аренды заданий и общего файлового хранилища.
- Перенос в S3 требует адаптера `ImageStorage` с сохранением UUID объектов и операциями чтения, удаления и перечисления. API продолжает отдавать файл через сервер с проверкой сессии.

На существующей ВМ код автоматически не обновляется. Перед отдельным развёртыванием потребуется PostgreSQL, каталог файлов и разрешение записи в systemd (`ReadWritePaths` для этого каталога): текущая служба имеет `ProtectSystem=strict`. Ресурсы маленькой ВМ нужно проверить перед размещением PostgreSQL. Служба уже использует `/etc/ai-reader/ai-reader.env`.

## Проверка реализации

11 ноября 2026 года: `mvn package` — 37 тестов без ошибок и пропусков, включая интеграционные проверки PostgreSQL 17.5. Для включения тестов БД задайте `AI_READER_POSTGRES_TEST_URL`, `AI_READER_POSTGRES_TEST_USERNAME`, `AI_READER_POSTGRES_TEST_PASSWORD`; используйте отдельную тестовую БД. Без этих переменных три теста PostgreSQL пропускаются; остальные тесты не обращаются к платным API.

С существующим ключом владельца выполнена одна реальная иллюстрация через HTTP API: `202 → READY`, получен JPEG 1024×1024. Проверены объединение двух одинаковых запросов, выдача готового результата из кэша без новой генерации и `404` для другой сессии. Проверка очистки удаляет просроченные метаданные, файлы и файлы без метаданных, сохраняя действующие результаты. Проверка перезапуска приложения выполняется отдельно без повторного платного запроса.
