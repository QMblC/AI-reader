# AI-reader

Backend приложения для чтения литературы с помощью ИИ. Принимает выделенный фрагмент текста, окружающий контекст и сведения о книге, чтобы вернуть перевод и объяснение смысла фрагмента.

**Версия:** 1.0. **Стек:** Java 21, Spring Boot, Maven.

## Возможности

- `POST /api/v1/analyses` — анализ текста с ответом из полей `translation` и `explanation`.
- `GET /actuator/health` — проверка состояния приложения.
- Swagger UI — `/swagger-ui/index.html` после запуска приложения.
- Валидация входных данных и формата ответа модели.

Анализ поддерживает два режима: Yandex при `YANDEX_ENABLED=true` и локальную заглушку при выключенном флаге. Подготовка промпта и обращение к модели выделены в отдельный логический модуль, чтобы подключать и заменять провайдеров без изменения контроллера.

Системный промпт подготовлен в [analysis-system.txt](src/main/resources/prompts/analysis-system.txt) и загружается приложением при запуске. Он задаёт перевод выделенного фрагмента на русский, краткое объяснение с учётом контекста и JSON-ответ с полями `translation` и `explanation`. Пользовательский текст передаётся отдельно от инструкций. Качество ответов реальной модели требует отдельной проверки с действующим ключом.

## Настройки Yandex

Для включения модели задайте `YANDEX_ENABLED=true`, `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` в окружении процесса Java и перезапустите приложение. Spring проверяет настройки `YandexProperties`, создаёт HTTP-клиент и подключает `YandexLlmClient` к `POST /api/v1/analyses`. Сам запуск приложения не вызывает модель: запрос отправляется при обращении к endpoint анализа. По умолчанию флаг выключен и используется `StubLlmClient` без ключей и сетевых запросов.

| Переменная окружения | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `YANDEX_ENABLED` | `false` | Выбрать Yandex вместо локальной заглушки |
| `YANDEX_API_KEY` | — | API-ключ; обязателен при `YANDEX_ENABLED=true` |
| `YANDEX_FOLDER_ID` | — | Только идентификатор каталога, без `gpt://` и имени модели; обязателен при `YANDEX_ENABLED=true` |
| `YANDEX_MODEL` | `yandexgpt-5.1` | Имя модели |
| `YANDEX_BASE_URL` | `https://ai.api.cloud.yandex.net` | Базовый адрес API |
| `YANDEX_TEMPERATURE` | `0.2` | Параметр генерации от 0 до 1 |
| `YANDEX_MAX_TOKENS` | `1500` | Максимальное число токенов ответа; больше нуля |
| `YANDEX_CONNECT_TIMEOUT` | `5s` | Таймаут соединения; не менее `1ms` |
| `YANDEX_READ_TIMEOUT` | `60s` | Таймаут ожидания ответа; не менее `1ms` |

Переменные передаются процессу Java через окружение, **Environment variables** в конфигурации запуска IDEA или Docker `--env-file`. Spring Boot самостоятельно `.env` не загружает. Ключ хранится только на сервере. При выключенном флаге настройки Yandex не загружаются и ключ не требуется; при включённом неверные или незаполненные обязательные настройки останавливают запуск приложения.

Если в AI Studio скопирован полный URI `gpt://<идентификатор_каталога>/yandexgpt-lite`, в `YANDEX_FOLDER_ID` нужно указать только часть между `gpt://` и следующим `/`. Имя модели задаётся отдельно через `YANDEX_MODEL`. Полный URI в поле каталога отклоняется при запуске.

В ответах `503` поле `providerStatus`, если оно есть, содержит исходный HTTP-статус Yandex. Поле `code` уточняет категорию: `LLM_PROVIDER_BAD_REQUEST` (`400`), `LLM_AUTHENTICATION_FAILED` (`401`), `LLM_ACCESS_DENIED` (`403`), `LLM_PROVIDER_NOT_FOUND` (`404`), `LLM_PROVIDER_RATE_LIMIT` (`429`) или `LLM_PROVIDER_UNAVAILABLE` (остальные сбои). Код и статус также записываются в серверный лог; ключ, пользовательский текст и тело ошибки провайдера туда не выводятся. При сетевой ошибке без ответа `providerStatus` отсутствует.

Зафиксирован [контракт Yandex Completions API](docs/yandex-completions.md): HTTP-запрос, сообщения, JSON-схема результата и пример ответа провайдера. `YandexLlmClient` использует настроенный Spring `RestClient` с таймаутами из окружения и принимает результат только при HTTP `200`. `YandexCompletionResponseParser` проверяет структуру ответа, завершённость генерации (`finish_reason: stop`), роль `assistant`, отсутствие отказа и непустой текст модели. Проверку JSON внутри текста выполняет общий `JsonAnalysisResultParser`. Ошибки ответа модели возвращаются как `502`, ошибки доступности — как `503`. Ограничения размера ответа, общий срок выполнения и политика повторов остаются следующим этапом.
