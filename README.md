# AI Reader Backend

Серверная часть MVP мобильного приложения для интерактивного чтения литературы с помощью искусственного интеллекта.

Приложение позволяет читателю выделить фрагмент текста и получить контекстный разбор: перевод, объяснение идиом, сленга, метафор и других особенностей авторского языка. Backend принимает текст и окружающий контекст от мобильного клиента, формирует запрос к языковой модели и возвращает результат.

> **Статус:** репозиторий подготовлен для начала разработки. Исходный код Spring Boot приложения, инструкции по запуску и автоматизация сборки будут добавлены позднее.

## Технологии

- **Язык:** Java.
- **Backend:** Spring Boot.
- **LLM:** модели через Yandex Cloud.
- **Контроль версий и совместная работа:** GitHub.

Версии Java и Spring Boot, инструмент сборки и остальные зависимости будут зафиксированы при инициализации проекта.

## Объём MVP

Планируемые задачи серверной части:

- Принимать от мобильного приложения выделенный фрагмент текста и окружающий контекст.
- Формировать контекстный запрос к LLM для объяснения смысла, а не только буквального перевода.
- Безопасно обращаться к Yandex Cloud LLM без раскрытия ключей на стороне мобильного приложения.
- Возвращать мобильному приложению результат анализа в согласованном формате.
- Обрабатывать некорректные запросы, ошибки и недоступность внешнего сервиса.

**Не входит в текущий объём backend MVP:**

- Авторизация и управление учётными записями. При наличии времени авторизация может быть реализована позднее как отдельный микросервис.
- Код мобильного приложения, включая EPUB-ридер, навигацию и сохранение прогресса чтения: он хранится в отдельном репозитории.
- Генерация иллюстраций сцен — необязательная возможность после реализации основных требований.

Конкретные API-контракты будут согласованы с командой мобильной разработки и документированы по мере реализации.

## Совместная разработка

Над backend работают два разработчика в одном репозитории. Используем упрощённый **GitHub Flow**:

- `main` — основная ветка; в неё попадают проверенные изменения.
- `feature/<name>` — новая функциональность, например `feature/llm-integration`.
- `fix/<name>` — исправление ошибок.
- `chore/<name>` — настройка проекта, зависимостей и инфраструктуры.
- `refactor/<name>` — изменение структуры кода без изменения поведения.

**Порядок работы:**

1. Обновить локальную `main` и создать от неё отдельную ветку для задачи.
2. Реализовать изменения и необходимые тесты, отправить ветку в GitHub.
3. Открыть Pull Request в `main` с кратким описанием изменений и способом проверки.
4. Получить ревью второго разработчика, устранить замечания.
5. После проверки выполнить **Squash and merge** и удалить временную ветку.

В `main` напрямую не коммитим. Не создаём постоянные персональные ветки: новая задача — новая ветка. При изменении внешнего API согласуем контракт с командой мобильного приложения.

## Локальный запуск

Пока Spring Boot проект не инициализирован, команд для сборки и запуска нет. После добавления исходного кода здесь появятся:

- требования к окружению;
- команды сборки и запуска;
- пример конфигурации без секретов;
- инструкция по подключению к Yandex Cloud в тестовом окружении.

**Важно:** API-ключи, токены и другие секреты нельзя добавлять в репозиторий. Настройки должны передаваться через переменные окружения или другой защищённый механизм.

## CI/CD

На начальном этапе CI/CD не настроены. После появления проекта планируется автоматизировать сборку и тестирование Pull Request; развёртывание (CD) будет рассмотрено отдельно.
